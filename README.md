# 요기코퍼레이션 예산 대시보드 (Next.js)

HTML 파일로 주고받던 **부서별 예산 대시보드 + 통합예산 대시보드**를 하나의 Next.js 앱으로 옮긴 것.
부서 화면에서 입력하면 MongoDB 의 부서 문서에 바로 저장되고, 통합 화면은 그 문서들을 실시간으로 합산한다(작성본 HTML 을 주고받거나 불러올 필요 없음).

| 화면 | 주소 | 내용 |
|---|---|---|
| 통합 예산 | `/` | 전체 매출 현황(매출 예산안 + onlineData 실적 비교) · 전체 예산 현황 · 인원현황 · 부서별 원장(마감/해제) · 부서별 백데이터 |
| 부서 예산 | `/dept/<부서코드>` | 가이드라인 · 코드설명표 · 2027년 인원정보 · 계정별 예산 · 백데이터 |

부서코드(공통 0017 은 숨김 — `HIDDEN_DEPTS`, `src/lib/templates.ts`. 탭·합계·계정 관리·로그인에서 빠짐, DB 문서는 그대로): `0001` 임원 · `0002` 경영지원 · `0004` 마케팅 · `0005` 디자인 · `0011` 영업 · `0016` 온라인고객지원 · `0017` 공통 · `0020` 물류

## 로그인·권한
| 팀 | 아이디(처음) | 들어갈 수 있는 곳 |
|---|---|---|
| 경영지원 | `mgmt` | 통합예산(`/`) + 모든 팀 페이지 + **계정 관리** 탭 |
| 임원 | `exec` | `/dept/0001` |
| 마케팅 | `marketing` | `/dept/0004` |
| 디자인 | `design` | `/dept/0005` |
| 영업 | `sales` | `/dept/0011` |
| 온라인고객지원 | `onlinecs` | `/dept/0016` |
| 공통 | `common` | `/dept/0017` |
| 물류 | `logistics` | `/dept/0020` |

- 모든 계정의 처음 비밀번호는 **1234**(`INITIAL_PASSWORD` 로 변경 가능, 계정이 처음 만들어질 때만). 계정 관리 화면에 ‘초기 비밀번호’로 표시된다.
- 경영지원이 계정 관리 탭에서 팀별 **비밀번호 변경(새 비밀번호 직접 입력, 8자 이상 영문+숫자)·아이디 변경·사용 중지**. 저장한 비밀번호는 해시라 다시 볼 수 없다(잊으면 새로 바꾼다). 비밀번호를 바꾸면 그 계정으로 로그인해 둔 화면은 다시 로그인.
- 팀 계정은 자기 팀 페이지·자료만(다른 팀 주소는 자기 페이지로 돌려보내고 API 도 403). 목표매출 수정·마감 해제·작성본 불러오기·수수료는 경영지원만. 마감은 팀이 직접 할 수 있다.
- 비밀번호는 scrypt 해시로만 저장, 로그인은 12시간 유지(서명 쿠키, `SESSION_SECRET`). 같은 아이디로 5번 틀리면 5분 잠금.
- 경영지원 비밀번호를 잊었으면 `npm run admin:reset-password` (새 비밀번호를 화면에 한 번 보여 줌).
- **로컬 마스터**: `.local/.env` 에 `LOCAL_MASTER=1` 이면 이 PC 개발 서버(`npm run dev`, `http://localhost:6400`)는 로그인 없이 **마스터**(경영지원 권한 전체)로 열린다. 개발 모드 + localhost 요청에서만 동작하고 배포 서버(production·Vercel)에서는 무시된다. 팀 계정으로 로그인해 두면 그 팀 화면이 우선(로그아웃하면 다시 마스터). 개발 서버는 `127.0.0.1` 에만 열려 사내망 다른 PC에서는 접속되지 않는다. 코드: `src/lib/auth/local.ts`.

## 실행

```bash
npm install          # node_modules 는 Dropbox 동기화 제외 표시가 된 폴더(이미 표시됨)
npm run dev          # http://localhost:6400
```

- 환경 변수는 **`.local/.env`** (Dropbox 동기화 제외 폴더). 바꾼 뒤에는 서버를 껐다 켠다. 항목 설명은 `.env.example`.
- `MONGODB_URI` 가 비어 있으면 **로컬 파일 저장소(`.local/dev-db`)** 로 동작한다 — 시험용. 화면 위에 안내가 뜬다.
- 시험으로 넣은 값을 MongoDB 로 옮기려면 주소를 넣은 뒤 `npm run migrate:file-to-mongo` (기존 Mongo 값은 보존, 덮어쓰려면 `-- --force`).

### MongoDB 연결 (Atlas)
1. Database Access → Database Users → Add New Database User — 비밀번호 방식, 권한은 `readWrite` @ `yogico_budget` 만.
2. Network Access → IP Access List — 이 PC IP 추가(배포 시 `0.0.0.0/0`).
3. Clusters → Connect → Drivers → Node.js 주소를 복사해 `<db_password>` 를 바꾼 뒤 `.local/.env` 의 `MONGODB_URI` 에 넣는다. DB·컬렉션은 처음 저장할 때 자동으로 생긴다.

### 매출 실적 (onlineData MCP)
- 서버가 onlineData MCP(cloudtype, `/mcp`)의 `online_offline_compare` 도구를 호출해 월별 온라인·오프라인 실적을 가져온다. 결과는 DB `cache` 에 보관(올해 3시간·지난해 24시간), 화면의 ‘실적 새로 가져오기’로 즉시 갱신.
- 이 앱 전용 토큰이 `.local/.env` 의 `ONLINEDATA_MCP_TOKEN` 에 들어 있다. **cloudtype onlineData MCP 서비스 환경 변수 `MCP_TOKENS` 끝에 `,yogico-budget:<그 토큰>:read` 를 붙이고 재배포**하면 연결된다.
- 기준: 온라인 = 이카운트 출고(자사몰+스마트스토어+외부채널, 공동구매 제외), 오프라인 = 매장 주문서. 목표의 ‘(매출) 온라인’·‘(매출) 오프라인’ 행과만 비교한다.

## 저장 규칙
- 부서 문서 하나 = 계정별 예산(계정→행→12개월, 계산식·메모) + 인원정보 + 목표매출. 입력 후 0.7초 뒤 자동 저장.
- 구역(계정·인원·목표매출)마다 저장 번호가 있어 다른 화면이 먼저 저장했으면 **덮어쓰지 않고** ‘변경 충돌’ 안내(최신 불러오기 / 내 내용으로 저장).
- **마감**하면 계정·인원·첨부는 조회만 가능(통합 화면 부서 탭에서 ‘마감 해제’). 목표매출은 통합 담당자 입력이라 마감 후에도 수정 가능.
- 목표매출 → 통합 매출 예산안 채널로 자동 합산(매출 구분 이름이 채널과 같아야 함). 수수료(오프라인·PG·VAT)는 통합 화면에서 입력.
- **목표매출 입력**: 마케팅·영업·온라인고객지원은 부서 화면 가이드라인 1번 표에서 직접 입력(`SALES_INPUT_DEPTS`, `src/lib/templates.ts`) — 팀이 넣은 값은 마감되면 막힌다. 경영지원은 통합 화면 ‘전체 매출 현황 → 부서별 월별 목표매출’ 표에서 모든 부서를 바로 고친다(마감 후에도 가능).
- **매출 예산안**은 기본으로 접혀 연도별 (손익계산서) 매출액·(ERP) 매출액 4줄만 보이고, ‘펼치기’로 채널·수수료까지.
- 첨부파일은 DB(`attachments`)에 저장, 1개 10MB 까지(`MAX_ATTACHMENT_MB`). Vercel 은 요청 4.5MB 제한.

MongoDB 컬렉션: `departments`(`_id` = `2027:0011`) · `attachments` · `revenue_plans` · `cache`

## 엑셀 내려받기
- 계정 상세 창의 **엑셀 다운로드** → 그 계정 표 그대로(`2027_부서_계정_상세예산.xlsx`). 계정별 예산 화면의 **엑셀 다운로드** → 부서 전체(시트1 계정별 요약 · 시트2 상세 내역).
- 화면과 같은 모양(노란 머리행·구분/계정 칸 합치기·합계 행 색·천 단위), **메모 = 엑셀 메모(빨간 삼각형)**, 계산식(=10000*4)은 엑셀 수식, 합계는 SUM/SUBTOTAL 수식(요약 시트는 상세 시트 소계를 참조). 내려받기 전에 저장 대기 중인 값을 먼저 저장한다. 만드는 곳: `src/lib/excel.ts`(ExcelJS).

## 엑셀 업로드
- 계정별 예산 화면·상세 창의 **엑셀 업로드** — 이 앱에서 내려받은 엑셀(부서 전체 ‘상세 내역’ 시트 또는 계정 하나 파일)을 고쳐 올리면 계정과목·구분·상세설명으로 행을 찾아 금액·계산식(숫자·사칙연산)·메모를 반영. 파일에만 있는 행은 새 행으로 추가, 이 부서에 없는 계정과목은 건너뜀. 팀 계정은 🔒 경영지원 입력 줄을 바꿀 수 없어 건너뜀.
- 서버(`POST /api/departments/[코드]/excel`, `src/lib/excelImport.ts`)는 합친 결과만 돌려주고, 화면에서 ‘바뀌는 행 n개’를 확인한 뒤 평소 저장 경로로 저장. 5MB 까지, 마감된 부서는 안 됨.

## 상세 입력 창 행 관리
- 모든 행에 **수정**(구분·상세설명)·**삭제**, 아래 **+ 행 추가**(같은 구분이 있으면 그 묶음 바로 아래). 🔒 경영지원 입력 줄은 팀 화면에서 버튼이 없다. 같은 구분이 이어지면 구분 칸을 합친다(직접 추가한 행도).

## 같은 화면 접속 표시 · 실시간 커서
- 같은 부서 자료(부서 화면 `/dept/코드` + 통합 화면의 그 부서 탭)를 보고 있는 다른 계정을 화면 위 ‘같은 화면’ 줄에 표시(수정 중/보는 중·보고 있는 탭). 같은 아이디를 여럿이 쓰면 ×2.
- 다른 사람의 마우스가 **계정 아이디 꼬리표가 달린 커서**로 따라다니고, 누른 곳은 물결, 입력 중인 칸은 테두리(‘design 입력 중’)로 보인다. 상세 입력 창 위에서도 보인다(top layer).
- 위치는 좌표가 아니라 ‘가까운 `data-anchor` 영역 → 그 안 몇째 표의 몇 행 몇 칸 → 칸 안 비율’로 주고받아 화면 크기·스크롤이 달라도 같은 칸을 가리킨다(`src/components/Presence.tsx`).
- 신호는 `POST /api/presence` 를 같은 화면에 다른 사람이 있으면 0.6초, 혼자면 5초, 탭을 내려 두면 15초마다(웹소켓 없이 — Vercel 에서도 동작). Mongo `presence` 컬렉션, 1분 지나면 자동 삭제(TTL). 로컬 마스터는 남이 보이기만 하고 자신은 표시되지 않는다.

## 경영지원 전용 계정(급여 등) 보호 · 수정 기록
- 전 줄이 🔒 경영지원 입력인 계정(직원급여·퇴직급여·세금과공과금 등, `isSensitiveAccount`)은 **팀 계정에 금액을 보내지 않는다**(부서 문서·저장 응답·충돌 응답·엑셀·2026 실적 모두, `src/lib/sensitive.ts`). 팀 화면은 ‘•••’, 연간 예산 카드에 ‘급여 등 제외’. 팀이 저장하면 서버가 그 계정을 원래 내용으로 다시 채운다.
- 경영지원은 원장·상세 창·손익 탭에서 ‘•••’ → [🔒 비밀번호 확인]으로 비밀번호를 한 번 더 넣으면 그 창(탭)을 닫을 때까지 보인다(`POST /api/auth/verify`, 틀리면 400, 5번 틀리면 5분 막음). 넣는 비밀번호 = 계정 관리 탭에서 정한 **급여 열람 비밀번호**(`/api/auth/view-password`, 경영지원 계정에 해시, 로그인 비밀번호와 다르게), 정하지 않았으면 경영지원 로그인 비밀번호. 잊으면 로컬 마스터에서 다시 정한다. 엑셀도 확인 뒤에만 급여 등 포함(`?sensitive=1`).
- 계정마다 **마지막 수정 기록**(일시·팀 ID·IP)을 서버가 남긴다(`lastEdit`, 내용이 바뀐 계정만). 상세 창 위·급여 계정 줄에 표시, IP 는 경영지원에게만. 로컬 마스터(개발용)는 확인 없이 보이고 기록을 남기지 않는다.

## 계정과목 노출 (경영지원)
- 통합 화면 **계정과목 노출** 탭 — 계정과목 30개 × 부서 표에서 체크하면 그 부서에 보이고, 끄면 그 부서 팀 화면의 계정별 예산·엑셀 다운로드·업로드에서 빠진다(경영지원 화면에는 흐리게 ‘숨김’). 줄마다 ‘안 쓰는 부서 숨기기 / 모두 보이기’.
- 금액이 들어 있는 부서는 숨길 수 없다(팀이 못 보는 금액이 합계에 남지 않게). 팀이 숨긴 계정을 고치면 서버가 403. 저장: Mongo `settings` 컬렉션(`2027:visibility`, 저장 번호로 충돌 방지), 바꾸면 팀 화면에 몇 초 안에 반영.

## 실시간 반영
- 누가 값을 고치면 같은 부서를 보는 다른 화면(팀 화면·통합 부서 탭)과 통합 합산 화면에 새로고침 없이 바로 반영(시험: 경영지원→팀 1.2초, 팀→통합 2.8초).
- **통합예산(경영지원) 우선**: 구역별 마지막 저장자(`savedBy`)를 남긴다. 팀이 저장하다 충돌했는데 그 구역을 경영지원이 먼저 저장했으면 [내 내용으로 저장] 없이 경영지원 값으로 자동으로 맞추고 안내한다(팀끼리 충돌은 지금처럼 선택). 경영지원이 고친 뒤 팀이 최신 값을 보고 다시 고치는 것은 허용.
- 접속 신호(`/api/presence`) 응답에 부서별 저장 번호(`sync`)를 실어 보내고, 번호가 올라간 구역(계정·인원·목표매출)만 다시 받아 온다. 내가 고치는 중인 구역은 덮어쓰지 않음(저장 때 기존 충돌 안내). 통합 화면은 어느 부서·매출 예산안 번호든 바뀌면 합산을 다시 불러온다.

## 경영지원 입력 줄 · 2026 실적 · 손익
- 전 줄이 경영지원 입력인 계정(직원급여·퇴직급여 등)은 팀 화면에서 "상세"가 없고 눌러도 창이 열리지 않는다(금액은 원장에 보임). 경영지원·마스터는 열 수 있음.
- **경영지원 입력(🔒) 줄**: 코드설명표의 @인사부·@경영지원·@회계부 항목 — 직원급여 전체, 퇴직급여, 세금과공과금, 건강보험·고용산재 회사분, 화재보험료, 보증보험료(마케팅 제외), 회사 행사(Employee day·워크샵·Cinema day), 자사몰 포인트. 팀 화면에서는 조회만, 경영지원이 입력하고 상세 창에서 줄마다 잠금을 켜고 끈다(서버도 같은 규칙). 잠금 생기기 전 문서는 처음 열릴 때 잠금만 붙는다(금액 그대로).
- **2026 실적**: 원본 HTML 데이터의 행별 실적(대부분 1~3월분)을 상세 창 맨 오른쪽 칸에, 월별 값은 금액 칸에 마우스를 올리면. 출처 `src/data/templates.json`(`npm run extract`).
- **손익 탭(통합)**: 매출액(손익계산서) − 매출원가 = 매출총이익 − 판관비(전 부서 30개 계정) = 영업손익, 2026(원본 손익표 전년값) 대비. 매출원가(제품·상품)는 손익 탭에서 경영지원이 입력(`revenue_plans.cogs`).

## 검토 의견 (경영지원 → 팀)
- 경영지원이 팀 화면의 **검토 의견** 탭이나 통합 화면 팀 탭(원장 아래)에서 첨언·수정 요청을 남긴다. 대상은 부서 전체 또는 계정·월.
- 팀은 자기 의견을 보고 **답글**만(작성·반영 완료·삭제는 경영지원). 반영 필요 의견이 있으면 팀 화면 위에 안내, 계정별 예산 표에 💬 표시, 상세 창 위에 의견 표시.
- 경영지원이 **반영 완료**로 닫는다(다시 열기 가능). 통합 화면 전체 예산 현황 표에 팀별 반영 필요 수. 저장: `reviews` 컬렉션.

## 인원정보
- 경영지원: 모든 팀 인원 추가·수정·삭제·순서 변경(▲▼). 영업 계정: 매장 직원(매장 직급·직급 빈 행)만 추가·수정·삭제·순서 변경, 본사 인원은 조회만. 다른 팀: 조회만. 서버에서도 같은 규칙으로 막는다.
- 원본에 없던 직급: 물류 ‘부장’, 영업 매장 직급 ‘중간관리’(영업 계정이 직접 입력) — `scripts/extract-from-html.mjs` 의 `EXTRA_POSITIONS`·`EXTRA_STORE_POSITIONS`.
- 영업은 매장명 → 직급 순, 통합 인원현황에는 ‘매장명/직급’. 인원이 없는 공통(0017)은 인원현황에서 뺀다.

## 기존 HTML 작성본 옮기기
통합 화면 → 전체 예산 현황 → **HTML 작성본 불러오기**. 부서 작성본·마감본 또는 통합 작성본 HTML 을 고르면 부서별 내용을 미리 보여 주고, 고른 부서만 DB 에 반영한다(마감된 부서 제외).

## 원본 HTML 에서 템플릿 다시 뽑기
`npm run extract` — 상위 폴더의 HTML(통합 1개 + `2027년_부서별_예산_대시보드/*.html`)에서 계정·행 구성, 가이드라인, 코드설명표, 2026 매출 참고값, 수수료 초기값을 `src/data/*.json` 으로 다시 만든다. 이미 만들어진 부서 문서는 바뀌지 않는다(처음 만들 때만 사용).

## 참고
- **webpack 으로 실행하는 이유**: Turbopack 은 Windows 에서 경로를 바이트로 세어 260 을 넘으면 실패하는데, 이 Dropbox 경로는 한글이 많아 걸린다. `npm run dev`/`build` 는 `--webpack` 을 쓴다(Linux 배포 환경에서는 둘 다 무관).
- 배포할 때는 호스팅 환경 변수에 `SESSION_SECRET`(32자 이상 무작위)을 꼭 넣을 것 — 없으면 운영에서 로그인이 동작하지 않는다. 실제 입력 전에 모든 계정을 초기 비밀번호(1234)에서 바꿔 전달할 것.
